PocketBump 1.2 真实双电脑校园网复测（由试玩者执行）

状态：待双方实机复测并检查报告。本机双窗口与 Development 诊断不能替代此项。
保留原 PocketBump1.0、PocketBump1.1 文件夹、压缩包和此前的双方故障报告。
两台 Windows 电脑使用同一个完整 PocketBump1.2 压缩包，核对 SHA256SUMS.txt 和 build-info.json 的 build_guid。
1.2 保持协议 8，与 1.0（协议 7）不兼容；不要混用不同版本的 exe 或数据目录。

1. 记录电脑/系统、校园网连接方式（有线或 Wi-Fi）、版本、build_guid、开始时间。
2. 核对各自规则面板显示的冲刺键。全新本地配置的 P2 默认 Num2（小键盘 2），已有有效绑定不会重置；LAN 本机玩家仍使用 P1 键位。
3. A 主机、B 加入：完成至少一场达到胜利条件的比赛，检查双方比分/胜者一致。
4. 连续重赛至少 3 次；尝试一方先同意、另一方稍后同意。
5. 检查 Dash、撞球、绿/蓝/紫 Buff、掉落复活、撞柱眩晕、碎墙与修复。
6. LAN 比赛中按 Esc，比赛应继续；关闭菜单恢复控制，不出现积攒的冲刺。
7. A 主动返回主菜单，B 应显示 PEER LEFT；重新建房并加入，再交换角色重复。
8. 连续玩 20–30 分钟，记录异常停顿、DESYNC、本机超时或对方报告的故障，不要把终止故障记录成主动离开。短暂等待不再弹出面板，不代表等待不存在；需结合报告判断。
9. 如果再次中断，先保留双方冻结画面的截图与对应 JSON；记录时间、谁先出现提示及当时的窗口状态。真正终止故障仍应显示提示，终止时间线应保留故障前采样，停留画面不会挤掉它。
10. 双方打开报告目录，主动提交相同时段的 JSON 和必要的 Player.log，并保留原文件。报告可能含局域网端点，不自动上传。

不要求关闭防火墙、改变 NumLock 或修改校园网络策略；当前没有自动重连，终止后从菜单重新建连。
故障通知通过 UDP 尽力发送，丢失时另一方可能独立超时；并非每次双方都会收到同一种提示。
时间线为有限频率采样，不是抓包；单凭接收计数不能证明丢包由哪一台网络设备造成。
两台电脑的时钟可能不同，不应仅按双方 JSON 的 UTC 时间排序来判断故障先后；需结合会话身份、Tick、故障来源及各自时间线。
待双方报告检查后才能评价原校园网问题是否解决；没有再发生一次故障也不能保证所有局域网都可靠。
