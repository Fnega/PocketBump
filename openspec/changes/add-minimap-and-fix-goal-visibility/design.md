## Context

基线0.13正式Arena使用固定北朝上的倾斜正交跟随相机；`orthographicSize=10.5`，偏移`(0,20,-12)`，北侧focus最多23.4。蓝门横梁中心`(0,2.42,36.2)`投影Y约1.082，靠近仍被裁切；橙门横梁投影约0.037。旧测试只复述clamp公式而未检查门框。HUD每视口顶部有状态和拾取信息，右上为旧网络提示。用户明确要求小地图右上、网络提示右下，两者同时保留。

## Goals / Non-Goals

**Goals:**
- 靠近任一球门的正面通道时，完整门框与入口落在HUD以外的安全区域，主角色仍可见。
- 右上全场等比例北朝上小地图，显示双方位置/朝向、所有活动球、两门和柱/墙状态；本地每侧一张、LAN一张。
- 正式场景可编辑的UI及有界显示工作量；只读模拟，支持回滚/重赛/复活状态更新。

**Non-Goals:**
- 不修改场地/门坐标、规则、碰撞、得分、输入、协议或PRNG；不改变大地图为全场镜头。
- 不做可点击传送、缩放/旋转交互、迷雾、额外渲染相机、外部素材或新音效。不宣称同机测试等于双电脑网络验收。

## Decisions

1. 用UGUI轻量Graphic绘制地图而非额外Camera/RenderTexture。统一世界x/z到地图坐标，以完整场地和门外观余量作等比例映射；图标有对比边缘，玩家用朝向三角和P1/P2身份，本机额外描边。活动球逐个显示（1–8），死亡玩家不冒充存活箭头；碎墙不画为实体，待修复显示轮廓。只读当前已校正模拟，无视觉独立计时或Unity物理。
2. 每SeatView绑定一个右上小地图，LAN沿现有座位选择仅显示本机Region。状态/拾取条预留右侧地图宽度。网络面板序列化为右下锚点，暂时等待与终局错误逻辑/手动菜单保持不变；小地图不因网络提示隐藏，暂停时随模拟保持位置。
3. 相机从倾角投影、实际门框/入口视觉bounds及HUD安全区域推导端区可见范围；允许端区必要的向门方向偏移及少量场地外背景。维持固定倾角/尺度/北朝向，不改球门几何来绕过问题。偏移在进入端区时平滑过渡；正常靠近门口的两门正面通道（横向门宽附近、纵向最后8单位）验收完整入画，远离球门不保证主画面全场可见，由小地图提供定位。传送/复活仍安全重置历史。
4. 增量工具只增加/绑定小地图、给现有个人UI留位和移动网络面板；执行前保存原Arena字节备份，不重建世界、菜单或美术。运行时不每帧覆盖作者颜色/布局。新组件使用已有主题和字体，N标识使用已有ASCII字形。
5. 基线规范尚未同步，visual-presentation的网络等待Requirement按已实施变更完整块修改，记录后续同步依赖；不为本功能擅自归档旧变更。

## Risks / Trade-offs

- [倾角及HUD遮挡使单纯放宽clamp仍不够] → 使用真实bounds投影和UI矩形交叠断言，不只检查相机中心或门中心。
- [小窗口/半屏太窄] → 地图等比例缩放且状态条预留空间，验证1280×720、1920×1080、1024×768，实际查看PNG。
- [北门可见导致画外背景增多] → 仅端区有限偏移，保留世界模型和玩法尺寸；不扩大地图或添加碰撞。
- [回滚、蓝传送和复活图标过时] → 从当前模拟每次刷新，隐藏非活动实体、无额外缓存权威状态，测试checksum不变。
- [旧测试/截图期待右上网络框] → 同步更新位置断言、捕获检查和诊断说明，不弱化网络功能测试。

## Migration Plan

先单测/PlayMode复现裁切，再接入小地图与相机、增量更新正式Arena，保存三尺寸实际Unity画面。关闭用户编辑器后才运行独立batch；当前只读检查未发现Unity/Player进程。回归通过后重查版本顺延完整Development包（预计0.14），复制原许可，运行本机双进程smoke及展示检查。保留0.13和新失败证据；回退用旧完整包或精确备份，不重置用户工作树。

## Open Questions

无待确认的布局选择。2026-10-07用户已确认右上北朝上地图、本地每侧一张/LAN一张，并明确网络提示改右下；蓝门问题确认靠近且LAN也出现。新的玩法/美术扩大范围仍须另行询问。
