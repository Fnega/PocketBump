## Context

仓库是 Unity 2022.3 URP 2D 空工程，只有 SampleScene，无玩法脚本、无联网包。第一版要在现有 Physics2D 上做出可玩的同机双人桌，规则已在探索中拍板：纵轴打珠、横轴灌人、一口定局、3 秒半场热身后再出珠。

约束：体量小、无解谜、不把联机物理同步做进这一版。

## Goals / Non-Goals

**Goals:**

- 一张可读的 2D 物理桌：上下袋只吃珠、左右口只吃人，中线闸门可开关。
- 同机两人能打完一盘：开球 → 得分 → 重置 → 先到获胜分且领先 2 分。
- 获胜分与每局珠数可在进入对局前调整。
- 状态机把「倒计时 / 进行中 / 得分冻结 / 盘结束」分清，避免进球后继续撞。

**Non-Goals:**

- 联机、房间、延迟补偿、主机权威同步。
- 技能、道具、多张桌子、剧情、解谜。
- 新输入系统包、ECS、自定义物理引擎。
- 珠的差异分值（每颗珠进袋都是 1 分）。

## Decisions

### 1. 同机双人先于联机

- **选择**：第一版只做键盘分边的本地对打。
- **原因**：碰撞手感、守门是否过强、1 颗珠开球是否太抢中，都必须先在无延迟环境里调。联机是后续变更。
- **备选**：一开始上 Netcode —— 体积和规则验证绑死，否决。

### 2. 口袋用图层过滤，而不是「同一个洞两种物理」

- **选择**：上下袋触发器只检测珠图层；左右口触发器只检测玩家图层。珠在左右口有实体挡板，玩家在上下袋有实体挡板。
- **原因**：人比珠大，做不到诚实的同一孔隙。街机过滤一眼能用颜色/盖板读出来。
- **备选**：全触发器无挡板 —— 珠会进左右口，破坏规则。

### 3. 谁的袋谁得分，不问 last-touch

- **选择**：珠进入某端袋口触发器 → 该袋主人 +1。人进入任一左右口 → 另一名玩家 +1。
- **原因**：乱堆连锁下 last-touch 会吵；袋归属和「掉洞送分」同一哲学，也好测。
- **备选**：last-touch —— 实现更烦，联机时更烦，第一版不做。

### 4. 同一物理帧只记 1 分

- **选择**：一帧内若同时满足多种得分，按固定顺序只取第一件：左右灌人（P1 掉优先于 P2 掉）→ 北袋 → 南袋。然后立刻进入得分冻结。
- **原因**：一口定局。双进球会把比分一次加两分，和「一局一分」冲突。
- **备选**：都算分 —— 否决。

### 5. 比赛状态机

```
Kickoff  --3s, 闸门关, 人可在己半场动-->  Live
Live     --第一分-->  Scored（短冻结，展示谁得分）
Scored   --重置桌面-->  Kickoff   或  MatchOver（已达获胜条件）
```

- **选择**：闸门是独立碰撞体，Kickoff 启用、进入 Live 时禁用；珠只在进入 Live **之后**生成，初速为零。
- **原因**：倒计时里不能先碰到珠；人可以卡位但不能越线。
- **备选**：倒计时冻住玩家 —— 用户要求可随意动，否决。开门与出珠同一帧 —— 贴线者瞬间持珠，可作为后续手感旋钮，默认仍「先开门再出珠」（同一帧末尾生成即可，闸门已关碰撞）。

### 6. 出生与珠的放置

- **选择**：玩家出生在己方半场的几何中心（北半场中心 / 南半场中心），不是贴在中线上。默认 1 颗珠放在场地正中、静止。珠数 > 1 时在正中附近无重叠簇拥，仍在中线附近、闸门打开后才出现。
- **原因**：贴线出生会让 3 秒移动无意义。
- **备选**：贴线出生 —— 否决。

### 7. 设置数据

- **选择**：`MatchSettings`（ScriptableObject 或对局前 UI 写入的运行时配置）：`pointsToWin`（默认 8，范围 1–21）、`marbleCount`（默认 1，范围 1–8）。设置项对外可叫「获胜分 / 珠子数」；「对局数」不另做 BO 盘数。
- **原因**：一盘就是一盘，用获胜分表达先到 N；珠数是节奏旋钮。
- **备选**：BO3 外加每盘 8 分 —— 第一版不做。

### 8. 胜负

- **选择**：玩家分数 ≥ `pointsToWin` 且领先 ≥ 2 则盘结束。7–7 后进入 Deuce，打到差 2。第一版不设无限 Deuce 封顶。
- **原因**：与探索结论一致。封顶留到真有 20–20 再加。

### 9. 玩家运动

- **选择**：`Rigidbody2D` + 力或速度混合，有质量与碰撞，才能把珠撞进袋、把人对手撞进左右口。P1：WASD；P2：方向键。无跳跃。
- **原因**：碰碰乐的表达就是冲量。旧 Input Manager 已在工程里，不必为第一版加 Input System 包。
- **备选**：Transform 平移 —— 碰撞假，否决。

### 10. 场景与代码结构

- **选择**：主场景一张桌；`MatchDirector` 持状态机与分数；`Arena` 持袋口、闸门、出生点；口袋组件只负责「谁进来了」事件。不引入网络对象。
- **原因**：物体少，一个导演类够把重置做原子。

## Risks / Trade-offs

- [守门过强] → 上下袋口宽于玩家碰撞，珠可从身侧漏过；出生在半场中心逼人出来抢珠。
- [1 颗珠变成开门抢球] → 接受为默认节奏；珠数做成设置，调到 3–8 可对比。
- [乌龙过多] → 珠初速必须为零；簇拥不要带朝向某一袋的偏置。
- [3 秒 × 局数拖时间] → 第一版保持 3 秒；过拖再收到 2 秒，不当成规则核。
- [2D 物理穿透/抖动] → 珠数上限 8；连续碰撞检测开在玩家与珠上。
- [无限 Deuce] → 第一版不封顶；若体验差再加软顶。

## Migration Plan

- 在 `Assets/Scenes/` 增加或改造对局场景，SampleScene 可留作废。
- 无数据迁移。回滚即不进入该场景。

## Open Questions

- 开门与出珠是否错开 1–2 帧（贴线抢珠过强时再加）。
- Deuce 是否要封顶（第一版不做）。
- 得分冻结展示时长（建议 0.75–1.25 秒，实现时用常量，不进设置）。
