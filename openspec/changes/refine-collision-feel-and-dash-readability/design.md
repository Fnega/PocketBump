## Decisions

### 1. 单独的手感规则版本，保留已发布 V1

V1 配置、既有 ContentHash、LayoutHash 及其模拟分支作为 A/B 基线保持不变，不原地修改 `CreateProductionV1`。当前候选规则描述普通附加量策略和反冲参数：初段 6 Tick、初段速率 8、尾段倍率 6（即 48 单位/秒）。先用于开发/测试入口；批准后生成独立、不可变的新生产快照并切换正式入口，不增加供普通玩家自行混搭物理参数的菜单。旧 3 倍候选可在测试中以相同参数快照重建，验证新旧内容身份不同而布局不变，不覆写旧报告。

布局完全相同；不得直接提升同时参与布局哈希的 `RulesRevision` 来伪装手感变更。新的手感版本/参数仅进入新配置的内容身份，保留旧 V1 哈希编码路径。候选与正式快照的 provisional 身份分别记录，不能将候选测试哈希直接改写成正式证据。

替代方案：直接调整 Builder/V1 默认值虽简单，但会丢失可靠对照、悄然改变旧身份，故不采用。

### 2. 只对非 Dash 的附加推动使用碰前权重

沿用现有闭合速度 `closing > 0`、单位碰撞法线及每接触事件锁存条件。采样必须发生在本次基础冲量更改速度之前，不能从碰后速度反推撞击强度。

定义 `n` 为玩家指向球的当前求解法线，三个输入均取碰前值：

- `drive`：玩家 `ControlVelocity` 沿 n 的非负投影。
- `approach`：玩家总速度 `ControlVelocity + ExternalVelocity` 沿 n 的非负投影。
- `relative`：玩家相对球速度沿 n 的非负投影。
- 普通权重 `w = clamp01(min(drive, approach, relative) / NormalSpeed)`。
- 本次普通附加球速为 `NormalShotImpulse × w × GreenMultiplier`，方向仍为 n；无绿色时倍率为 1。

这样静止玩家被来球击中、完全切向移动、纯外力推着走以及因反冲正在背离球的玩家不会凭空获得普通主动附加推动；基础碰撞仍照常发生。`ControlVelocity` 在旧实现也承载静态响应，本轮不追溯输入意图或重构这个通道，规则准确表述为“具备控制通道法向分量且实际上向球接近”，不承诺只由当前按键决定。

正常满速正撞静止球时 w=1；更低主动接近速度的附加量单调不增。Dash 分支不使用此曲线：原有有效闭合、锁存、固定 12 及绿色倍率原样保留，包括斜向 Dash 的现行规则。绿色只乘附加量，最终总球速仍受原 48 上限限制；不能要求绿色后的最终球速严格等于原总球速的 1.5 倍。

玩家互撞附加冲量、球与球、静态障碍和危险球额外击退算法不在此修改范围。持续接触不补发附加推动；新接触仍由原来的分离/锁存判定。

替代方案：按总相对闭合速度独自给权重会把高速来球的能量误当玩家主动击球；连 Dash 一起缩放则超出用户仅细化普通低速碰球的确认。本方案同时避免这两点。

### 3. 动态外力分段衰减（最新互撞幅度修订见第 9 节）

新增玩家权威状态 `RecoilGraceTicks`（名称可按代码风格调整），候选初值/复位值为 0。V1 路径仍恒按 8 衰减且该字段恒为 0；新手感路径只在合格的新动态接触中给实际收到外力的玩家设置为 6。

合格接触必须同时满足：当前 pair 未锁存、碰前确有闭合速度、本次基础与附加响应后该玩家实际 `ExternalVelocity` 发生变化且不为零。比较接受前后值，不能只看传入 delta：紫色免疫、零冲量、同向增量已被速度上限完全裁剪，均不启动窗口。同一次接触里的多次 AddVelocity 合并判定、至多重置一次；已锁存接触的基础解算仍运行，但不得不断续期。另一实体或分离后真正再碰撞可重新开始一段窗口，这是一次新的真实受撞。

时间线明确为：在 Tick T 碰撞之后置 6；T+1 至 T+6 的 `UpdatePlayer` 先用 8/60 衰减，再消耗一个计数；T+7 起用 48/60。不得在 `AdvanceTimers` 先减一次而只保留五次初段更新。沿现有 `MoveTowards` 方式靠近零，不改变外力方向、不越过零，也不乘控制输入瞬间抵消。实际外力归零时计数同时归零。

静态墙柱仍通过原响应路径处理，不启动或重置窗口，也不对其 `ControlVelocity` 应用尾段衰减。外力和静态碰撞先后相遇时沿用原求解顺序；轨迹可能因较早的动态尾段衰减而改变，但这不等于修改静态碰撞系数或眩晕规则。

| 事件 | 新阶段状态处理 |
| --- | --- |
| 新的、实际收到动态外力的接触 | 设置为 6，保持该次初始冲量原样 |
| 持续接触/同次重复求解/零增量/免疫 | 不重置；现有物理约束继续 |
| 正常更新或眩晕中的更新 | 随现有外力衰减位置消耗；眩晕时长不改 |
| 静默输入等待、故障暂停、本地暂停、终局 | 没有实际外力更新就不推进，不按墙钟过期 |
| 进球展示冻结 | 跟随现有外力不更新行为保持；重新开球时清零 |
| 掉落、复活、成功传送、双方归位、新比赛 | 和既有速度清零一起置零 |
| 传送失败 | 速度和阶段均保持原样 |

该候选只承诺“相同首次冲量、前六步相同、后段更快衰减”，不承诺所有碰撞都在 0.3～0.5 秒恢复或停车。已有反向运动/多物体碰撞会影响实际轨迹；测量与用户试玩决定是否正式采用。

替代方案：提高正常刹车会改变未受撞的移动；覆盖 ExternalVelocity 会消灭击退；在每次 AddVelocity 调用重置计数会让持续接触永不进入尾段，均不采用。

### 4. 状态/规则身份先于 LAN 步进达成一致

新字段必须进入深复制、恢复、完整状态比较及新手感配置的校验 schema；仅改单个阶段计数也必须改变该 schema 的校验值。旧 V1 使用原 schema/语义并保持字段为零；新配置使用包含手感阶段的版本化 schema，禁止在相同内容身份下切换校验编码。

沿用完整 ContentHash 的现有 Join/JoinAck 比较，在任何游戏 Tick 之前拒绝 V1、候选、新生产配置之间的不同身份。此次没有输入/报文载荷变更，预期保留协议 8，以规则内容身份区分模拟兼容性；若实施发现既有握手不能可靠隔离校验 schema，先报告并修订方案，不通过扩大回滚窗口或忽略校验解决。

数值与计时完全在 60 Hz 模拟中计算；本地、LAN 与回滚重演走同一代码。补测乱序/延迟输入跨碰球、初段/尾段切换、再次受撞和速度清零时，最终完整状态与按时输入一致。静默等待期间指标和外力阶段不走墙钟，恢复后不重复碰球附加量、不丢或重复 Dash 边沿。

### 5. 本地共享地面粗环，LAN 保留原视口标记

2026-10-25 本地改为两个真正位于世界 XZ 地面平面的粗环，每个机器人一个，两台本地相机都能看到双方完整进度。位置跟随机器人 Root 的插值位置，世界朝向固定，不跟随 Facing 旋转或 Motion 的上下跳动/挤压。使用普通深度测试，不绘制穿墙置顶 UI；不新增相机、碰撞体、地图信息或游戏计时器。

本地两环都读取 `1 - remainingTicks / DashCooldownTicks`；亮色部分从空到满。候选初始外半径约 1.12、带宽 0.24、离地约 0.055，使用明亮队色、暗色底轨和描边。仅 Ready 可以闭合亮色环；冷却最后几 Tick 保留最小可辨缺口，避免光栅化让未就绪误看作满环。该最小缺口只影响显示，不影响倒计时或 Dash 资格。Dash 中、眩晕和非 Live 使用空/禁用样式，死亡隐藏。

本地新环启用期间隐藏四个旧 HUD 标记及原 `Identity footprint` Renderer，避免重复圈；停用、切回 V1 或进入 LAN 时恢复原 Renderer 启用值。旧对象与样式不得删除或重写。新环仅接入已有候选，不借本次反馈切换正式默认。

LAN 暂不适配粗环，完整保留 `SeatView.Region` 和现有 camera/seat 规则：使用 GameplayCameras[0]，本方细环显示进度、对手仅固定二态。不得把本地双方完整进度的授权扩展到 LAN；本轮不启动 LAN 诊断或 Socket 验收。

状态优先级与现有 HUD 一致：

| 模拟状态（按优先级） | 本方标记 | 对方标记 |
| --- | --- | --- |
| 死亡 | 隐藏 | 隐藏 |
| 非 Live / 开球锁定 | 固定禁用样式，无就绪高亮 | 固定未就绪样式 |
| 眩晕 | 固定禁用样式，保留已有头顶“晕” | 固定未就绪样式 |
| Dash 正在进行 | 固定 Dash 中样式，不把 cooldown=0 误画为完成 | 固定未就绪样式 |
| 冷却中 | 按剩余 Tick 填充的进度环 | 本地同样显示粗环进度；LAN 固定未就绪样式 |
| 可 Dash | 满环及就绪符号 | 固定就绪符号 |

“就绪”表达当前模拟中的 Dash 资格，不取代已有暂停菜单/故障遮罩；暂停或等待时保持冻结模拟对应的状态，不制造冷却继续完成的假象，也不恢复已隐藏的等待面板。本轮采用持续状态样式，不新增一次性就绪闪光或声音，避免回滚造成重复播放。

每次状态展示都能响应同 Tick 回滚修正、进球/新 epoch、传送/复活，不以 Tick 只能递增或本机 `Time.deltaTime` 倒计时为前提。标记只读模拟，不创建权威计时或修改输入。

### 6. 可读性、遮挡与编辑器持久性

标记使用现有青蓝/橙身份色、深色描边、不同几何形态；不借用绿色/紫色整圈光罩，不覆盖 Buff、球、晕字、小地图或网络操作。UI 不接收射线输入。可见性按本视口判定：镜头后、屏幕外以及被实体完全遮住的对手不显示；不夹到屏幕边、不新增穿墙/离屏/小地图 Dash 情报，不改变既有障碍淡化规则。使用每相机可见性/深度正确的表现实现，不把 `Renderer.isVisible` 的任一相机可见结果当作所有视口可见。

正式 Arena 中保存指示器对象、主题参数和序列化引用，编辑器可检查/调整；运行时仅绑定、定位、更新状态，不在 Awake/Bind 覆盖用户样式。通过显式幂等增量编辑器入口接入，保留未知子物体、手工颜色/模型/场景修改，不全量重烘焙 Arena，不改 MainMenu 或 Build Settings。复用项目已有 UI 图形/字体，不下载资源。

初轮未采用共享精确环以限制对手信息；2026-10-25 用户已明确要求本地双方完整进度，因此只在本地采用共享地面环。LAN 不改变该信息边界。仅写 HUD 数字不能满足“看角色读状态”，全局重新烘焙会覆盖用户编辑，仍不采用。

### 7. 分层证据和最终手感确认

先固定 V1 对照，再分别验证普通推动、反冲候选、视口表现，避免把改变全部参数后的结果误归因。量化碰球矩阵包含速度 0/2/6/12、正碰/30°/60°、来球/追球、控制与外力反向、绿色/紫色、两座位镜像；有效 Dash 作为旧基准不变的回归。比较应区分基础响应、附加量和球速上限。

反冲记录首次外力、前 6 次更新、第 7 次更新、尾段归零时间、实际位移与逆向输入轨迹；使用不碰其他物体的夹具证明同起点下尾段缩短，再单独验证复杂接触。测试完整状态而非只比一个校验值。

界面验证本地两视口、LAN 两座位以及 1280×720、1920×1080、1024×768，覆盖遮挡/屏边、各状态优先级、同 Tick 修正、等待恢复和可编辑持久性。自动坐标/截图检查不等于用户读得懂，最后仍需实际观看。

上述为初轮证据范围。2026-10-25 新验收只针对本地粗环：两侧视口都展示双方进度，180/90/1/0 Tick、Dash/晕/开球/死亡、平面与朝向、角色跟随、重叠和普通深度遮挡、保存/重载/退出后样式。可用 staged `lan` 参数检查新环不会进入旧 LAN 表现分支，但不启动网络会话。初轮报告保留，不用旧截图代替这轮实际画面。

在候选可玩后请用户对照确认“轻碰是否可控、反冲是否仍有力度且能补防、双方 Dash 是否看得懂”。未获确认不得宣称正式手感定稿、切换发布用生产配置或勾选最终接受任务。若用户要求改新数值或其他规则，先更新本方案并重新确认范围。

### 8. 本地地图开关和可自定义快捷键

## Risks / Trade-offs

- [Risk] 权重取碰后速度、只看相对闭合，或把外力倒退误判主动射门。→ 碰前同时约束驱动/实际接近/相对接近，并为反例建立测试。
- [Risk] “其他规则不动”被错误理解为所有未来轨迹都不变。→ 固定未授权公式和参数；允许三项改动自然导致后续位置/进球结果不同，逐层对照首次响应。
- [Risk] 同接触反复续期或第 6/7 步边界偏移。→ 接触事件级重置、实际增量判定、明确 T+1…T+6 与 T+7 测试。
- [Risk] 新阶段漏校验或旧新身份相同导致 DESYNC。→ 版本化 profile/schema、V1 金样保护、握手先拒绝和全状态重演验证。
- [Risk] 投影 UI 泄露对手进度、穿墙显示或遮住球。→ 每视口独立引用、粗粒度对手状态、遮挡/裁剪/清晰度验收。
- [Risk] 候选更“快”却不更好玩。→ 保留 V1 对照和用户最终采用门槛，不以测试通过替代体验结论。
